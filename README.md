# F3 多渠道货源与舱位提单动态配载

把二十天里按小时陆续产出的货源，配到有时间窗、敏感品等级和单子仓限制的舱位
提单上，产出一行一条、能被逐条核对的明细。程序只读解析资料包里的两个 xlsx，
用整数化体积做精确守恒，按小时滚动、事件触发重排、增量补货，最后给出配货
明细、七项指标、独立约束审计、场景与规模实验、未配满原因诊断、离线看板
和方案报告 PDF。

## 快速开始

```
python -m pip install -r requirements.txt
python run.py
python run.py --self-check
python tests/run_tests.py
```

`python run.py` 默认跑全流程（stage=all），一次产出
`results/allocation.csv`、`indicators.csv`、`audit_report.json`、
`diagnosis.csv`、`metrics_scenarios.csv`、`scale_experiments.csv`、
`baseline_comparison.csv`、`dashboard.html`、`方案报告.pdf`、`figures/`、
`build_manifest.json` 等。`python run.py --help` 看全部参数，
`--only solve` / `--only core` 等可分段重跑。

默认 `data_dir` 是 `../F3_一舱装满_资料包/data`（相对项目根），可用
`--data-dir` 覆盖；两个 xlsx 全程只读引用，不复制进项目目录。
完整命令、退出码、逐条复现步骤与反查方法见 `docs/08_运行说明.md`，
依赖版本与三级降级方案见 `docs/09_依赖说明.md`。

## 实现边界

五条硬约束是：货源体积守恒、单提单配货不超过计划体积、单提单只提一个子仓、
敏感品等级兼容、提货时间窗。注入点匹配是软目标，不是硬约束。限重、耗材上限、
计费重、集装板尺寸、清关资质、可混配组合这六类规则既不实现，也不出现在
未配满原因诊断里；「计划起飞时间」「24 小时匹配」「半配惩罚」同样只是参考
字段、软目标或背景描述。

评估范围（2026-10-03 00:00 到 10-17 23:00）是货源方数类指标的统计范围，
不是可参与配载的货源范围；全 480 小时的货源都参与配载，`allocation.csv`
输出全量明细。配满率与虚仓提单数量是提单侧口径，按完整配载结果与全部 2652 张
提单统计，不受评估范围限制，口径见 `docs/06_指标口径.md`。「未配提单货量」是
供给侧剩余、没配到提单上的货源方数，不是提单缺口；提单缺口由「虚仓提单数量」
与配满率反映。

文档没写明的口径一律取最小、保守的假设，逐条写明假设内容、采用依据和影响，
见 `docs/05_假设清单.md`（全部标注「自行假设，非文档要求」）。
启发式不保证全局最优，也不保证覆盖真实 Pareto 前沿，只给三个采样点之间的
非支配关系。队名、成员、指导老师、AI 调用费用与投入时长用户未提供，
`docs/11_作品说明单.md` 与 `docs/12_AI协作记录.md` 相应字段留空并标
「待队伍填写」，不得编造；未完成与降级项如实记在 `docs/13_未完成项.md` 与
`results/build_manifest.json`。
