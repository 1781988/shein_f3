## 2. 产品定义

### 2.1 产品目标（三个互相独立）

1. **合规可审计**：产出的配货明细能按 5 条硬约束逐条核对，零冲突；被排除的规则既不实现、也不出现在诊断里。
2. **多目标可解释**：按文档给定的优先级顺序求解，给出不同优先级顺序场景下 7 项指标的对比，每个指标的公式、分母、统计范围都写在方案文档里，结果可复算。
3. **交付完整可复现**：文档要求的交付物齐全，自己假设的口径集中写明，从原始 xlsx 出发按运行说明能重跑出同样结果，且不把资料包数据带进公开产出。

### 2.2 用户故事

- 作为评委，我希望逐条核对配货明细、按 5 条硬约束检查每一行，以便确认没有体积守恒、敏感品、时间窗冲突。
- 作为看方案的人，我希望看到不同优先级顺序下 7 项指标怎么变，以便判断目标冲突时的取舍依据。
- 作为复现核验人员，我希望按运行说明从原始 xlsx 重跑，得到一致的明细和指标，以便确认结果不是手工拼出来的。
- 作为业务侧读者，我希望方案文档把文档没写明的口径集中列清楚，以便知道哪些是数据规定、哪些是作者自己假设的。
- 作为评分者，我希望看到自己实现的「先到先得」贪心基准对照和不同规模下的指标曲线，以便判断改进了多少。

### 3.2 UI Design Draft

这个项目的交付物以文件为主，材料没有要求图形界面。

- `allocation.csv`：列顺序与 README 示例一致，6 列打头；「货源渠道」「子仓」填原始 ID；同一提单多行时保持同一子仓。
- `indicators.csv`：3 列，一行一个指标，至少 7 行，口径说明写清公式、分母、统计范围。
- 方案报告 PDF 建议章节顺序：前 2 页作品说明单 → 问题与建模 → 口径与假设 → 算法 → 约束逐条审计 → 实验结果与规模曲线 → 如何复现 → 局限与风险。
- 选做看板（P1-2）单页：顶部 7 个指标卡，中部按小时的货源／配载时间轴，底部约束审计结果与未配满原因分布。
- 《作品说明单》《AI 协作记录》按各自模板原样填写，不删改模板结构。

## 4. 验收口径（可量化、可复核）

| 编号 | 检查项 | 判定 |
|---|---|---|
| V1 | 5 条硬约束逐条审计 | 对 `allocation.csv` 全量记录：同一提单配货方数之和 ≤ 计划体积；同一提单只出现一个子仓；每条记录的敏感品等级不高于该提单等级；提货时刻不晚于需求到站时间（异常提单用兜底值）；无负方数、无跨提单重复引用同一格货源。冲突数 = 0 |
| V2 | 体积守恒 | 按「小时 × 渠道 × 子仓」聚合，配出方数 ≤ 该格产出方数；保留 4 位小数后合计与原值之差 ≤ 0.0005 m³ |
| V3 | 明细格式 | UTF-8、逗号分隔、首行恰为 6 个列名；配货方数小数位 ≤ 4；产出小时匹配 `YYYY-MM-DD HH:MM` 且等于某个宽表列名的左端时刻；提货时刻匹配 `YYYY-MM-DD HH:MM:SS` |
| V4 | 指标文件 | `indicators.csv` 三列齐全，覆盖 7 项指标，口径说明非空，且与方案文档写明的公式一致、能从 `allocation.csv` 复算出来 |
| V5 | 场景对比 | ≥ 2 组不同优先级顺序，每组都给全 7 项指标 |
| V6 | 基线对照 | 贪心基准为自行实现（非调用现成基线），报告写明做法与假设；≥ 3 档实例规模，每档给配满率／时效／成本／耗时，给出曲线或等价表格与改进量 |
| V7 | 文档完整性 | 模型说明含决策变量、目标函数、5 条硬约束、推导与约束证明；假设章节逐条覆盖 A1—A5 且标注「自行假设」；方案报告一般不超过 10 页、前 2 页作品说明单且中文填写；AI 协作记录按模板填写 |
| V8 | 可复现 | 从原始 xlsx 出发，按运行说明重跑得到一致的 `allocation.csv` 与 `indicators.csv`（固定随机种子），附大致耗时；运行说明从解压目录出发逐条可照做 |
| V9 | 合规 | 公开产出（代码、报告、链接）不含资料包原始数据；被排除的 6 类规则既不出现在实现里、也不出现在诊断输出里 |
