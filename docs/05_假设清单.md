# 05 假设清单

材料里没写明的口径，一律按最小、保守的方式自己定，并在这里逐条写明。
**下面每一条都是自行假设，非文档要求。** 评审按这里写明的口径核对即可，
绝对数值不与其他队伍比较。引用依据时写具体出处，不把自定义口径说成资料包规定。

前五条（A1—A5）对应补充说明第七节列出的五类「由参赛者自行假设」，
后十三条（B1—B13）是文档完全没给、实现必须自己定的口径。
最后两条是本项目的实现取舍，同样属自行假设。

## A 类：补充说明第七节列出的五项

### A1 货何时算「被提走」

- **假设内容**：提单的「提货时刻」到达即视为货被提走；此前配货记录是软预留，
  可以退回改配。提货时刻由求解构造，且不超过最晚提货时间。
- **采用依据**：补充说明第五节 3 写「已配的货可以改配，只要还没被提单提走」，
  第七节把「何时算提走」列为自行假设。明细里唯一存在的时间点就是提货时刻，
  取它最保守，不额外引入一个数据里没有的时点。
- **影响**：决定滚动重排的有效窗口与到期锁定边界；不改动五条硬约束。与 B10、B12 联动。
- **标注**：自行假设，非文档要求。

### A2 每小时产出的货从哪一刻起可配、当天密度能否用于当天决策

- **假设内容**：每小时产出的货从该小时结束时刻起可配，即可配时刻 = 左端时刻 + 1 小时
  （`HH:00-HH+1:00` 的右端）。当天密度可用于当天决策，不引入未来货量预测。
- **采用依据**：补充说明第七节列为自行假设。取「货下线完成后才可配」最保守，
  不会把还没产出的货提前配走；密度表按封箱日期给定，属已知数据而不是未来信息。
- **影响**：可配时刻、提货时刻下界、积压计算起点；不增加硬约束。
- **标注**：自行假设，非文档要求。

### A3 正常提单是否受计划起飞时间约束

- **假设内容**：正常提单不受计划起飞时间约束，只按需求到站时间作最晚提货时间。
  233 张异常提单（最早提货晚于需求到站）按「最早提货 + 24 小时」兜底，且计划起飞
  时间同样不约束。计划起飞只是参考字段，不参与过滤、不进诊断。
- **采用依据**：文首硬约束清单只有五条；补充说明第四节 1—2 只给需求到站与异常兜底。
  若把计划起飞加成约束，等于新增第六条硬约束；数据里有 69 张计划起飞早于最早提货，
  加上去自相矛盾。异常兜底只针对那 233 张，不推广到全部提单。
- **影响**：候选过滤条件、审计 C5；硬约束集合不变。
- **标注**：自行假设，非文档要求。

### A4 杂费三列是否计入成本

- **假设内容**：杂费单价、杂费（按提单）、杂费重量取值三列不计入成本。
  报告记录「杂费非空的 2 张提单未计入成本」。
- **采用依据**：补充说明第七节列为自行假设；数据说明写明只有 2 张提单有值，
  文档没给计算口径。不计入最保守，量级影响可忽略。
- **影响**：成本指标数值，量级极小。写明后评审按此核对。
- **标注**：自行假设，非文档要求。

### A5 10.3—10.17 以外产出的货源能否参与配载

- **假设内容**：全 480 小时（全 20 天）的货源都参与配载，不丢弃任何非零格；
  指标统计范围以产出小时落在 2026-10-03 00:00—2026-10-17 23:00 的配货记录
  集合 A 为主：货源方数类指标严格只取 A，但配满率与虚仓提单数量是提单侧口径，
  按完整配载结果与全部 2652 张提单统计（见 B1/B2 与 `06_指标口径.md`）。
  `allocation.csv` 输出全量明细。
- **采用依据**：补充说明第六节 1 给的是「评估范围：10.3—10.17 产出的货源」，
  这是统计范围；第七节把「范围外能否参与配载」列为自行假设。`01_文档核对.md`
  第 8 节编号 4 已明确「评估范围」不等于「可配载范围」，编号 5 明确「无损」不能
  解释成 100% 配载成功。取「全量参与 + 指标限范围」同时满足两者。
- **影响**：**影响最大**。求解规模、七项指标数值、CSV 与指标统计范围不一致
  （已在 `08_运行说明.md` 写清）、规模实验取样范围。
- **标注**：自行假设，非文档要求。主理人已确认采用这一口径。

## B 类：文档没给、实现必须自己定的口径

### B1 四个比率与积压指标的量化

- **假设内容**：七项指标按统计范围分三类，不统一基于评估范围记录集合 A：
  ① 敏感品完全匹配率、时效积压率、主注入点选择率、成本严格只统计集合 A；
  ② 未配提单货量按 R 内产出减 R 内配出，是供给侧差值；
  ③ 配满率、虚仓提单数量是提单侧口径，用完整配载结果与全部 2652 张提单，
  不受 A 限制（B2 说明这处实现阶段对设计原式的偏离）。公式与分母见
  `06_指标口径.md`。时效积压率用
  超 24 小时时长 × 方数 / (A 内方数 × 360 小时)，并另输出超 24 小时配货方数。
- **采用依据**：补充说明第六节 3 明确「各项指标请根据以上说明自己量化」，
  且两个示例公式前面写着「例如」，不是规定公式。取可复算、同一分母族的一组定义。
- **影响**：七项指标数值、可复算性、`indicators.csv` 的口径说明列。
- **标注**：自行假设，非文档要求。

### B2 虚仓判定与「未配提单货量」的统计范围

- **假设内容**：虚仓提单数量 = 全部提单中「整体配载方数 Q(b) 小于计划体积减
  0.0001 立方米」的张数，含完全没配到的 Q(b)=0；完全虚仓张数另作辅助量。
  「未配提单货量」= R 内总产出 − R 内配出方数，是**供给侧剩余、没配到提单上的
  货源方数**，不是提单缺口。提单缺口由虚仓提单数量与配满率反映。
- **采用依据**：备注第 6 条只给「避免舱位提单虚仓」的定性要求，补充说明第六节 5
  只列指标名，没给判定标准与统计范围。架构设计 B1/B2 给的是评估范围口径
  （Q_R(b) 与 B_R）。实现阶段改为按提单整体配载结果统计这两项，理由是同一张
  提单可能同时从评估范围内外的货源拿货，只取 A 会把它误判成未配满；该调整属于
  实现阶段对设计原式的偏离，主理人在交付复核时确认接受。两种口径的数值都给出，
  评估范围口径作为辅助值写在 `06_指标口径.md` 与 `results/report_data.json`。
- **影响**：这两项指标的数值。S1 场景下未配提单货量为 0、虚仓提单数量 76 张，
  两者并不矛盾：评估范围内产出的 26200.2840 立方米已全部配出，但提单计划体积
  合计 36031.55 立方米大于全量货源 35239.6992 立方米，必然有提单配不满。
- **标注**：自行假设，非文档要求。

### B3 提货时间窗的精确不等式

- **假设内容**：闭区间，含边界。最早提货时间 ≤ 提货时刻 ≤ 最晚提货时间，
  且提货时刻 ≥ 该批货的可配时刻；异常提单最晚 = 最早 + 24 小时（精确到秒）。
  不涉时区换算。
- **采用依据**：补充说明第四节 1 只写「最晚提货时间：用提单表的需求到站时间」，
  未给精确不等式。取含边界、不额外收紧的最小口径。
- **影响**：候选过滤、审计 C5、提货时刻构造。
- **标注**：自行假设，非文档要求。

### B4 体积守恒的统计粒度

- **假设内容**：按「小时 × 渠道 × 子仓」逐格核算，配出方数 ≤ 该格原始体积；
  再按 README 口径做「四位小数求和 vs 原值」比对，容差 0.0005 立方米。
- **采用依据**：文首硬约束清单只列约束名；README 提交末段给容差。
  取最细粒度最保守，且容差对象是「合计 vs 原值」，不是每条记录。
- **影响**：审计 C1、守恒判定；与整数化约定一致。
- **标注**：自行假设，非文档要求。

### B5 成本里「体积」「单 kg 成本」「密度为空」的口径

- **假设内容**：成本里的「体积」取该笔配货方数；单 kg 成本按提单目的港代码从
  成本表取；密度按 (渠道ID, 子仓ID, 产出日) 从密度表取，密度为空则该笔成本记 0
  并统计缺失笔数，不插值、不用均值；包机整张计 0；杂费不计入（A4）。
- **采用依据**：备注第 5 条「注入点单公斤成本」措辞含糊；补充说明第二节 1
  明确提单注入点 = 目的港代码，成本表按目的港给值，按提单目的港取最自然；
  数据说明写明密度为空是因为当天体积为 0。
- **影响**：成本指标；密度缺失笔数写进报告。本项目 1447 行密度为空对应的是
  零产出日，评估范围内的配货记录全部命中了有密度的行，因此缺失笔数为 0。
- **标注**：自行假设，非文档要求。

### B6 「无损 / 全量货源」的解释

- **假设内容**：只解释为「明细可逐条追溯到 (提单, 渠道, 子仓, 产出小时) 且体积守恒」，
  **不**解释为 100% 配载成功。
- **采用依据**：`01_文档核对.md` 第 8 节编号 5：若解释成 100% 成功，

- **影响**：指标定义与目标设定；禁止为了凑配满率放松任何硬约束。
- **标注**：自行假设，非文档要求。

### B8 场景组与规模档的数量、实例怎么造

### B9 贪心基准的具体做法与假设

- **假设内容**：提单按 (最早提货时间, 提单号) 升序逐个处理；每张提单锁定第一个

- **采用依据**：官网 EVAL 与赛题评分维度要求「自己实现 + 写明做法和假设」，

- **影响**：改进量对照、基线可信度。`src/baseline.py` 不调用主求解器。
- **标注**：自行假设，非文档要求。

## 实现取舍（同样是自行假设，非文档要求）

### 取舍 1：重排只在可见提单集新增时触发，到期只做定稿锁定

- **假设内容**：全量重排改配只在首步、末步、以及「可见提单集新增提单」的事件步
  触发（实测 21 步）；其余 459 步只给未满提单补本步新释放的货。
  提单到达最晚提货时间时只做定稿锁定（构造提货时刻、锁定记录不可再改），
  不因此触发全量重排。
- **采用依据**：系统设计 1.4 / 4.2 把「可见提单集变化 / 新的非零货释放 /
  有提单到期」都列为事件步，但实测 480 步里有 295 步发生到期。若到期逐步触发
  全量重排，会退化成「几乎每步全量重算」，与性能红线冲突。到期锁定并不释放
  货源（货已经被提走），重排对剩余提单没有增益。取这个最小口径后，
  全 480 步单场景实测 8.56 秒，全流程含三场景 / 实验 / 报告也在几十秒量级。
- **影响**：耗时显著下降；改配机会集中在这 21 个事件步，两个事件之间新到的货
  按增量规则补，可能错过更优组合。解的确定性与五条硬约束不受影响
  （独立审计 C1—C5 冲突数为 0，同配置两次运行逐行相同）。
- **标注**：自行假设 / 实现取舍，非文档规定。主理人已确认采纳现状，不加开关扩展。

### 取舍 2：可见性按「已获知」累积，末步把窗口上界延伸到全部提单

- **假设内容**：提单一旦进入可见窗口就一直可见到定稿锁定为止，不是每天重新
  裁一次窗口；在时间轴末步把可见窗口上界延伸到全部提单最早提货时间的最大值
  （实测 2026-10-25 12:05），让轴外提单也获得一次配货机会。
- **采用依据**：补充说明第五节 1 给的是「站在当天视角，最早提货时间在当天及
  未来 2 个自然日内可见」，没有说要不要把已经见过的提单忘掉；`01_文档核对.md`
  第 5 节要求「按时间轴外的提单正常纳入可见性判断，不虚构截断」。实测有
  28 张提单最早提货早于 2026-10-01、7 张晚于 2026-10-22，若严格按每天窗口
  裁切，这些提单会被静默丢弃。累积可见 + 末步延伸可同时满足「已获知」语义与
  「不虚构截断」。
- **影响**：这 35 张轴外提单被正常纳入可见性判断；可见集随时间单调增长，
  事件步数量从「每天变化」收敛到自然日切换的 21 步；配货明细覆盖全 480 小时，
  七项指标仍只统计评估范围内的记录。

## 几个容易写错的地方

- 「评估范围」是统计范围，不是「只能用这段货配载」。
- 「24 小时」在备注第 3 条里是「一般」描述，不在五条硬约束内；
  它只进入积压指标的量化，不作为过滤条件。
- 补充说明第六节 3 的两个公式前面是「例如」，采用它是自定义，不是照抄规定。
- 异常提单兜底（最早 + 24 小时、计划起飞不约束）只用于那 233 张，不推广。
- 「无损」不能写成 100% 配载成功；否则未配提单货量与虚仓提单数量恒为 0。
- 注入点匹配不是硬约束；六类被排除规则既不实现也不进诊断。
- 文件名与编码是 README 的「建议 / 如」，按建议做最稳妥，但不写成硬要求。
