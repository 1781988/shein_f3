## 三、实际发生的降级项

生成期的降级状态如实写在 `results/build_manifest.json`，不假装生成成功。

| 项 | 三级降级链 | 当前状态 |
|---|---|---|
| 方案报告 PDF | fpdf2 + 系统中文字体 → 可打印 HTML（自带 @page 与 page-break-after）→ 仅 `docs/10_方案报告.md` 内容源 | 看 `build_manifest.json` 的 `report.pdf.status`；一般为 generated（fpdf2 2.9.0 + simhei.ttf）。若系统缺中文字体则走 HTML，manifest 明确写「PDF 未自动生成」及原因 |
| 规模曲线 | matplotlib PNG → 静态 SVG → 纯数据表 | 看 `build_manifest.json` 的 `figures.status` 与 `results/figures/curve_status.json`；matplotlib 不可用或单图失败时降级 SVG，连 SVG 也写不出时只剩 `scale_experiments.csv` 数据表 |
| 看板 HTML | 注入 `dashboard_data.json` → 模板缺失时给带提示的页面 | 看 `build_manifest.json` 的 `dashboard.status`；失败时 `dashboard_data.json` 仍可用 |

PDF 正文、看板、报告一律写「立方米」或 m3，不带上标字符 `³`：
黑体缺这个字形会触发 fpdf2 的缺字告警。只有 Excel 表头 `密度(kg/m³)`
作为数据列名必须原样匹配，属于列名不是正文，见 `docs/09_依赖说明.md`。

## 四、已知的口径与实现取舍

以下不是未做，但容易被当成「没交代」，列出来便于核对，逐条写在
`docs/05_假设清单.md` 并标注「自行假设，非文档要求」：

- 重排只在可见提单集新增 / 首步 / 末步触发（实测 21 步），到期只定稿锁定；
  480 步中 295 步有提单到期，逐步全量重排会退化成近每步全量重算。
- 可见性按「已获知」累积，末步把窗口上界延伸到全部提单最早提货时间的
  最大值（2026-10-25 12:05），以纳入 28 张轴前、7 张轴后提单，不虚构截断。
- 「未配提单货量」是供给侧剩余、不是提单缺口；S1 该值为 0.0000 立方米
  与虚仓提单数量 76 张不矛盾，见 `docs/06_指标口径.md`。
- 货源方数类指标严格只统计评估范围记录集合 A；配满率与虚仓提单数量是提单侧
  口径，按完整配载结果与全部 2652 张提单统计，不受 A 限制。`allocation.csv`
  输出全 480 小时全量明细，口径分工见 `docs/06_指标口径.md`。
- 配满率与虚仓提单数量改用提单整体配载结果 Q(b)，而非架构设计 B1/B2 原式的
  评估范围 Q_R(b) / B_R。这处属于实现阶段对设计原式的偏离，理由是同一张提单
  可能同时从评估范围内外拿货、只取 A 会误判成未配满；主理人在交付复核时确认
  接受该调整（不是一开始就拍板）。评估范围口径数值 0.915633 / 327 张作为辅助值
  保留在 `results/report_data.json`，逐条依据见 `docs/05_假设清单.md` 的 B1/B2。
- 近似 Pareto 只给三个启发式采样点之间的非支配关系，不是真实前沿。
