## 一 问题与建模

这道题要处理的是按小时陆续产出的多渠道货源，与有时间窗、敏感品等级、单子仓
限制的舱位提单之间的动态配载。输入共五张表：货源宽表 301 行 × 480 个小时列，
撑开后是 144480 个「渠道 × 子仓 × 产出小时」的供给格，其中非零格 65512 个；
提单 2652 张，计划体积合计 36031.55 立方米；全量货源 35239.6992 立方米，
评估范围（10.3—10.17 产出）内 26200.2840 立方米。

难点有四个。体积口径：宽表「合计体积」列是 480 小时列之和四舍五入到两位的结果，
单行最大差 0.0050 立方米，拿它做守恒基准一定对不上，只能用 480 个小时列的原始
四位小数。时间耦合：货按小时产出，提单有最早提货、最晚提货，以及「站在当天
只能看到当天及未来两个自然日提单」的可见窗口。多目标不是单目标加权：优先级是
固定的字典序，还要给出不同顺序下的对比。结果必须可复算、可复跑。

我们把决策变量写成「一条配货记录 = 一个 (提单 × 供给格) 组合的整数方数」，
目标写成五层字典序键（不做加权和），硬约束严格只有五条：货源体积守恒、
单提单配货不超过计划体积、单提单只提一个子仓、敏感品等级兼容、提货时间窗。
注入点主备匹配是软目标；限重、耗材上限、计费重、集装板尺寸、清关资质、
可混配组合这六类规则明确排除，既不进约束也不进未配满诊断。完整的决策变量、
目标函数、约束推导与构造期冲突证明写在 `docs/04_模型说明.md`。

## 二 口径与假设

材料没写明的口径一律取最小、保守的一种，逐条写在 `docs/05_假设清单.md`，
每条都标注「自行假设，非文档要求」。影响最大的一条是 A5：全 480 小时货源都
参与配载、不丢弃任何非零格；指标统计范围以产出小时落在 2026-10-03 00:00
—2026-10-17 23:00 的记录集合 A 为主，其中配满率与虚仓提单数量是提单侧口径，
按完整配载结果与全部 2652 张提单统计；`allocation.csv` 输出全量明细。补充说明
第六节 1 给的是评估范围，指的是统计范围，不等于可配载范围。

「无损 / 全量货源」只解释为明细可逐条追溯、体积守恒，不解释成 100% 配载成功。
「24 小时」只是备注里的一般描述，只进入积压指标量化，不作过滤条件。
异常提单兜底（最早提货 + 24 小时、计划起飞不约束）只用于那 233 张，不推广。
「未配提单货量」是供给侧剩余、没配到提单上的货源方数，不是提单缺口；
提单缺口由「虚仓提单数量」和配满率反映。S1 场景下未配提单货量为 0.0000 立方米、
虚仓提单数量 76 张，两者并不矛盾：评估范围内产出的 26200.2840 立方米已全部配出，
但提单计划体积合计 36031.55 立方米大于全量货源 35239.6992 立方米，
必然有提单配不满。七项指标的公式、分母、统计范围与复算步骤见 `docs/06_指标口径.md`。

## 三 算法与实现

整体是「滚动时域 + 候选生成 + 字典序打分（近似 Pareto）+ 改配 + 后处理审计」，
五段各自独立。核心链路只用 Python 标准库加 openpyxl 只读解析，不需要求解器、
数据框或前端构建。

时间轴 480 步按小时推进。每步释放刚结束那一小时的产出格，按决策时刻所在自然日
更新可见提单集，把到最晚提货时间的提单定稿锁定，给未满提单补货。为了避免
每步全量重算，只有首步、末步、可见提单集新增这些事件步触发全量重排改配
（实测 21 步），其余 459 步只补本步新释放的货。重排时把所有未锁定记录按逆序
退回供给账户，清空子仓锁定，再按当前场景优先级重新分配；退回用整数精确恢复。

供给格按可配时刻分 480 个桶，按 (子仓ID, 敏感品等级) 分桶索引，桶内按产出小时
排序，取货时从桶顶取，不做全表扫描。给一张提单找货时，先用五条硬约束把范围
收窄，再按场景字典序键排序候选，依次取量，同格合并为一行。五层键的层内统一
「越大越好」，层间严格字典序，换场景只置换层次顺序，不必重新调权重。
三组场景各产出一个解，做一次非支配筛选作为近似前沿的采样点。

贪心基准单独一个模块：提单按 (最早提货时间, 提单号) 升序逐个处理，锁定第一个
有货的子仓，供给按 (产出小时, 渠道ID, 子仓ID) 先到先给，不回头、不改配、
不优化软目标，只过五条硬约束。与主方案共用供给账户和硬约束检查，只换选择策略，
这样对照的是选择策略本身，不是两套实现的差异。

构造期逐笔调用硬约束检查并记录冲突计数；后处理审计是另一套独立代码，
重新只读打开原始 xlsx，拿 `allocation.csv` 逐行重算五条约束、体积守恒容差、
格式、指标可复算与两次运行的哈希，不信任求解器内部状态。

## 四 约束逐条审计

独立审计结果写在 `results/audit_report.json`，逐条给出检查数与冲突数。
实测 C1 逐格守恒、C2 计划体积封顶、C3 单子仓、C4 等级兼容、C5 时间窗
（含提货时刻上下界与可配时刻）五项冲突数全部为 0。构造期
`Solution.diagnostics.construction_conflicts` 同样五个分量全为 0。
体积守恒除逐格整数比较外，还按 README 口径做四位小数求和比对，容差
0.0005 立方米，整数运算下正常差值为 0。

配货明细严格 6 列，UTF-8 无 BOM、固定换行、四位小数；产出小时写宽表列名的
左端时刻，提货时刻按 `YYYY-MM-DD HH:MM:SS`。派生字段（敏感品等级、目的港、
是否评估范围、渠道注入点、密度）不写进 CSV，由 `src/audit.py` 从原始表只读反查。
自检 V1—V9 的逐项状态见 `results/selfcheck_report.md`。

## 五 实验结果与规模曲线

场景做 3 组：S1 文档顺序、S2 成本优先、S3 时效优先，每组给出七项指标，
结果在 `results/metrics_scenarios.csv`。规模做 3 档 25% / 50% / 100%，
用固定种子 20261001 从「渠道 × 子仓行 + 提单 + 小时列」确定性取子集，
每档都跑主方案与贪心基准，记录在 `results/scale_experiments.csv`；
改进量在 `results/baseline_comparison.csv`，曲线在 `results/figures/`。
完整的做法、假设、改进量与局限写在 `docs/07_实验报告.md`。

近似 Pareto 只给出这三个启发式采样点之间的非支配关系，不是真实前沿；
报告里明说方法与局限，不把采样点包装成最优解集。

## 六 如何复现

运行环境 Windows + Python 3.13.14 + openpyxl 3.1.5；可选 numpy 2.5.4、
matplotlib 3.11.2、fpdf2 2.9.0。从解压后的目录出发：

```
python -m pip install -r requirements.txt
python run.py
python run.py --self-check
python tests/run_tests.py
```

`python run.py` 默认跑全流程，产出 `results/` 下的全部 CSV、JSON、看板、报告与
日志；`--data-dir` 可覆盖原始资料包路径。随机种子 20261001 写在
`config/settings.json`，只用于规模实验的确定性子集抽样，主求解链路不用随机数，
全靠显式排序。两次全流程的 `allocation.csv` / `indicators.csv` SHA-256 一致，
值写在 `results/selfcheck_hashes.json`。复跑比的是 CSV 内容哈希，
耗时受机器影响不作判据。逐步命令、退出码与反查方法见 `docs/08_运行说明.md`。

## 七 局限与风险

- 启发式不保证全局最优，也不保证覆盖真实 Pareto 前沿，只给三个采样解的非支配关系。
- 改配只在事件步触发，不是连续重优化；两个事件之间新到的货按增量规则补，
  可能错过更优组合。子仓一旦在某一轮被锁定，该轮内不再换仓，下一轮重排才有机会重选。
- 各项指标公式是自定口径，只在本方案内部可比，不与其他队伍的绝对数值比较。
- 「未配提单货量 = 0」不代表所有提单都配满；提单计划体积合计大于全量货源，
  虚仓提单数量如实统计，禁止为凑配满率放松任何硬约束。
- 未来货量预测、并查集并行化、在线 Demo、演示视频都不做，属于可选或举例项，
  列在 `docs/13_未完成项.md`。
- 队名、成员、指导老师、AI 调用费用与投入时长用户未提供，
  `docs/11_作品说明单.md` 与 `docs/12_AI协作记录.md` 相应字段留空并标「待队伍填写」，
  没有编造。落地前还需要队伍补齐这些信息。
