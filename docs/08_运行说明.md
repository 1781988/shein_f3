# 08 运行说明

从解压后的目录出发，按顺序执行下面的命令就能重跑全部结果。全部命令都在
Windows + Python 3.13.14 上实测过，环境细节与依赖版本见 `09_依赖说明.md`。

## 从解压目录出发

原始资料包与本项目同级，目录形态：

```
<上级目录>/
  F3_一舱装满_资料包/
    data/
      中东大箱体积_渠道子仓_每小时_1001-1020.xlsx
      提单_1001-1020提交.xlsx
  allocation/
    run.py
    config/
    src/
    dashboard/
    report/
    docs/
    tests/
    results/            # 运行产出，提交给主办方，不进公开仓库
```

`config/settings.json` 里的 `data_dir` 默认是 `../F3_一舱装满_资料包/data`，
按项目根（`allocation/`）解析。两个 xlsx 全程只读引用，不复制进项目目录，
不写回、不落中间缓存；加载前后各算一次 SHA-256 确认源文件未变。
可用 `--data-dir` 覆盖，覆盖值按当前工作目录解析。

## 命令

```
python -m pip install -r requirements.txt
python run.py                          # 默认全流程（all）
python run.py --help                   # 参数说明
python run.py --self-check             # V1—V9 自检
python tests/run_tests.py              # 标准库 unittest 汇总入口
python -m compileall -q src tests run.py
```

分段重跑（可选，方便定位问题）：

```
python run.py --only load               # 只加载与校验，产出 data_issues.csv
python run.py --only solve              # 只跑三场景 480 步滚动求解
python run.py --only solve --scenario S1_文档顺序
python run.py --only baseline           # 只跑先到先得贪心基准
python run.py --only diagnose           # 求解 + 未配满原因诊断
python run.py --only core               # 加载→校验→求解→基准→诊断（不写全流程产出）
python run.py --data-dir <资料包 data 目录> --only core
python run.py --scale 0.5 --only core   # 只跑单档规模
python run.py --log-no-timestamp        # 日志去掉时间戳，便于逐行比对
```

`--seed` 必须是整数（默认 20261001），`--scenario` 必须是 settings.json 里
已有的场景名，`--scale` 必须在 (0, 1] 内，`--data-dir` 必须存在且含两个 xlsx。
参数非法时抛配置错误，退出码 2 并打印合法取值。

## 退出码

| 码 | 含义 |
|---|---|
| 0 | 正常 |
| 1 | 未预期异常，堆栈写进 `results/run.log` |
| 2 | 输入/配置/数据错误（文件缺失、表结构、数值时间非法、参数非法） |
| 3 | `--strict-no-overwrite` 时结果文件已存在 |

默认 `--strict-no-overwrite` 关闭：覆盖 `allocation.csv` / `indicators.csv`
等文件前会把旧文件移入 `results/_prev/`，日志里写明。开启该参数时改为报错退出码 3。

## 复现

主求解链路不用随机数，全靠显式排序；种子 20261001 只用于规模实验的
确定性子集抽样（`random.Random(seed)`），不要把结果理解成「算法有随机性」。
全局排序键集中在 `src/config.py`：提单按场景优先级键加提单号，
供给格按 (子仓ID, 敏感品等级, 注入点匹配, 产出小时, 渠道ID)，
输出记录按 (提单号, 产出小时, 渠道ID, 子仓ID)。

`--log-no-timestamp` 可让 `results/run.log` 去掉时间戳，便于逐行比对。
两次全流程的 CSV 一致性用标准库 `hashlib.sha256` 比对，写在
`results/selfcheck_hashes.json`：`python run.py --self-check` 的 V8 会
把全流程真跑第二次写进临时目录，逐一比对 `allocation.csv` 与
`indicators.csv` 的哈希。复跑比的是 CSV 内容哈希，耗时受机器影响不作判据。

实测大致耗时（Windows + Python 3.13.14，仅供参考）：单场景 480 步约 8—14 秒，
`python run.py` 全流程约 70 秒，`python run.py --self-check` 会再跑一次全流程
约 70 秒，`python tests/run_tests.py` 约 2 分钟。逐项真实结果与耗时写在
`results/selfcheck_report.md`。

## 怎么从 CSV 复算指标与反查派生字段

`allocation.csv` 严格 6 列、不加列；核对 C4 / 主注入点需要的敏感品等级、
目的港、渠道注入点、是否评估范围、密度都不在 CSV 里，从原始 xlsx 只读反查：

1. 用 openpyxl `load_workbook(read_only=True, data_only=True)` 打开两个 xlsx；
2. 宽表按 (渠道ID, 子仓ID) 这一行取「敏感品」与「渠道注入点」，
   480 个小时列的原始四位小数是体积守恒基准（不要用「合计体积」列）；
3. 提单表按提单号取计划体积、目的港代码、需求到站时间、最早提货时间、
   舱位可走敏感品类型；异常提单（最早提货 > 需求到站）最晚提货 = 最早 + 24 小时；
4. 密度表按 (渠道ID, 子仓ID, 封箱日期) 取「密度(kg/m³)」列，
   体积 / 重量列不用；成本表按目的港取单 kg 成本；
5. 按 `docs/06_指标口径.md` 的公式从 `allocation.csv` 逐项算：货源方数类指标
   筛出集合 A，配满率与虚仓提单数量用全量配货记录加原始表的计划体积，
   与 `indicators.csv` 的「数值」列比对。

`src/audit.py` 的 `build_raw_lookup` / `recheck_from_csv` 是这条路径的
独立实现，不复用求解器内部状态；`src/metrics.py` 的 `compute_from_rows`
可用 CSV 行加重新加载的原始表复算七项指标，自检 V4 直接调用它。
