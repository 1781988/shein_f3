# 07 实验报告

这份文件记录三组场景对比、三档规模实验、贪心基准的做法与假设、改进量，
以及近似 Pareto 的局限。全部数值来自 `python run.py` 的真实运行，
结果文件在 `results/` 下；指标公式、分母与统计范围见 `docs/06_指标口径.md`。
机器差异会影响 wall time，耗时不作为复现一致性判据。

## 一、实验设置

| 项 | 值 |
|---|---|
| 环境 | Windows + Python 3.13.14 + openpyxl 3.1.5；matplotlib 3.11.2、fpdf2 2.9.0 可选 |
| 随机种子 | 20261001（只用于规模抽样的确定性子集；主求解链路不用随机数） |
| 全量数据 | 301 行货源 × 480 小时，非零格 65512 个；提单 2652 张 |
| 全量货源 | 35239.6992 立方米；评估范围（10.3—10.17 产出）内 26200.2840 立方米 |
| 场景 | S1 文档顺序 / S2 成本优先 / S3 时效优先，各跑满 480 步 |
| 规模档 | 25% / 50% / 100%，每档跑主方案（S1）与自实现贪心基准 |
| 单场景 480 步耗时 | 实测 8—14 秒；全流程含三场景 / 实验 / 报告约 70 秒 |

规模抽样用 `random.Random(20261001)` 从「渠道 × 子仓行、提单、小时列」
各取一个确定性子集，不引入外部数据；抽样后重算反查索引与总量，
保证求解器拿到的是自洽的小实例。三档的固定种子相同，但每档独立初始化，
相同规模两次运行逐行一致。

配满率 0.915633、虚仓 327 张，写在 `results/report_data.json` 与看板辅助量里，
不作为 `indicators.csv` 的主值。

其他辅助量：集合 A 记录 50933 行 / 全量 68087 行；完全虚仓 52 张；
超 24 小时配货方数 7183.9889 立方米；成本计算里密度缺失笔数 0
（密度表 1447 行密度为空对应零产出日，评估范围内的记录全部命中了有密度的行）。

## 三、三组场景对比

`results/metrics_scenarios.csv`：

| 场景 | 配满率 | 完全匹配率 | 积压率 | 主注入点率 | 成本（元） | 未配提单货量（立方米） | 虚仓张数 |
|---|---|---|---|---|---|---|---|
| S1 文档顺序 | 0.978023 | 0.482304 | 0.033382 | 0.142502 | 84909701.11 | 0.0000 | 76 |
| S2 成本优先 | 0.896666 | 0.495629 | 0.112565 | 0.170264 | 81008158.40 | 473.4327 | 296 |
| S3 时效优先 | 0.978023 | 0.491875 | 0.013743 | 0.161247 | 84436560.96 | 0.0000 | 84 |

场景之间确实出现了取舍：把成本提到第一层（S2）把成本从 84909701.11 元
降到 81008158.40 元，但配满率掉到 0.896666、积压率升到 0.112565、
虚仓张数升到 296；把积压提到第一层（S3）把积压率压到 0.013743，
配满率与 S1 持平，成本略降。字典序键的层次顺序由配置驱动，
换顺序不必重新调权重，这是本方案做多目标对比的核心机制。

三组解的五维目标向量（越大越好，积压率与成本取负）做非支配筛选后，
非支配采样点为 **S2 成本优先、S3 时效优先**；S1 被 S3 支配
（S3 在配满率、完全匹配率、积压率、主注入点率、成本五维都不差于 S1，
且至少一维严格更好）。`results/report_data.json` 的「近似Pareto」段
列出了三个点的向量与筛选结果。

**这只是三个启发式采样点之间的非支配关系，不是真实 Pareto 前沿。**
真实前沿需要遍历或求解全部可行配载组合，本题规模下不可行；
启发式本身也不保证全局最优。改进只在可见集新增等事件步触发，
两个事件之间新到的货按增量规则补，可能错过更优组合。
这些局限在 `10_方案报告.md` 里也直说了。

## 四、贪心基准的做法与假设

`src/baseline.py` 是独立实现，不调用 `RollingSolver`（单测里锁住这一点）。

- 提单按 (最早提货时间, 提单号) 升序逐个处理，离线单趟跑完 480 小时；
- 每张提单锁定第一个有可用货的子仓，之后所有行都用这个子仓；
- 供给按 (产出小时, 渠道ID, 子仓ID) 先到先给，填到计划体积或无货为止；
- 不回头、不改配、不优化注入点 / 敏感品 / 成本 / 时效等软目标，
  只过五条硬约束；与主方案共用 `SupplyLedger` 和 `constraints.check_all`。

做法与假设是自定义的（`05_假设清单.md` B9），官网 EVAL 和赛题评分维度
只要求「自己实现 + 写明做法和假设」，没有指定做法。这样对照的是选择策略
本身，不是两套实现的差异。基准的构造期五条硬约束冲突数为 0。

## 五、相对基准的改进量（100% 规模）

`results/baseline_comparison.csv`，改进量按「越高越好 / 越低越好」调整符号：

| 指标 | 基准值 | 本方案 | 改进量 | 改进率 |
|---|---|---|---|---|
| 提单配满率 | 0.948563 | 0.978023 | +0.029460 | +3.11% |
| 敏感品属性完全匹配率 | 0.484384 | 0.482304 | −0.002080 | −0.43% |
| 时效积压率 | 0.064954 | 0.033382 | +0.031572 | +48.61% |
| 主注入点选择率 | 0.116519 | 0.142502 | +0.025983 | +22.30% |
| 成本（元） | 77085347.68 | 84909701.11 | −7824353.43 | −10.15% |
| 未配提单货量（立方米） | 838.5199 | 0.0000 | +838.5199 | 100% |
| 虚仓提单数量 | 222 | 76 | +146 | +65.77% |

如实说明：主方案在配满率、积压、主注入点、虚仓张数上明显优于基准，
但完全匹配率略降 0.002080、成本高了 7824353.43 元。这符合字典序优先级
（配满率排第一、成本排第五），不是「全面更优」。禁止为凑配满率放松
任何硬约束——独立审计 C1—C5 冲突数全为 0。

## 六、规模曲线

`results/scale_experiments.csv`，曲线 PNG 在 `results/figures/`
（matplotlib 3.11.2，4 张：配满率、积压率、成本、耗时）。
生成状态如实记在 `results/figures/curve_status.json` 与
`results/build_manifest.json`；matplotlib 缺失时降级静态 SVG，
连 SVG 也写不出时只剩这张数据表。

| 规模 | 方法 | 配满率 | 积压率 | 成本（元） | 耗时（秒） | 记录数 |
|---|---|---|---|---|---|---|
| 0.25 | 主方案 | 0.175931 | 0.000000 | 4405395.58 | 0.367 | 3688 |
| 0.25 | 贪心基准 | 0.175931 | 0.000808 | 3973111.41 | 0.092 | 3708 |
| 0.50 | 主方案 | 0.395520 | 0.000000 | 19301030.48 | 0.832 | 16007 |
| 0.50 | 贪心基准 | 0.395520 | 0.000013 | 13992400.65 | 0.559 | 16056 |
| 1.00 | 主方案 | 0.978023 | 0.033382 | 84909701.11 | 9.221 | 68087 |
| 1.00 | 贪心基准 | 0.948563 | 0.064954 | 77085347.68 | 2.166 | 65474 |

读法与局限：25% / 50% 两档同时抽了货源行、提单和小时列，
配满率在这两档明显低于 100% 档，因为分母（抽到的提单计划体积）与
分子（抽到的货源）不是按同一比例缩放，且部分提单被抽中却没有对应货源。
两档里主方案与基准的配满率相同，是「供给远小于需求、先到先给也能配完」
的结果，差异主要体现在积压率（主方案两档都是 0）和成本上。
耗时随规模单调上升，100% 档主方案 9.221 秒、基准 2.166 秒；
基准更简单所以更快，这是选择策略的代价，不是实现效率的差距。

## 七、复现方式

```
python run.py
python run.py --self-check
python tests/run_tests.py
```

`python run.py` 默认全流程，`--only solve --scenario S1_文档顺序` 可只跑单场景，
`--scale 0.5` 可只跑单档规模。实验数值写进 `results/` 下的 CSV 与
`report_data.json`；`06_指标口径.md` 给出从 `allocation.csv` 加原始表复算
七项指标的步骤，自检 V4 直接调用 `metrics.compute_from_rows` 逐项比对。
